HOW SYNC CHANGED
- Two-second revision checks read a small manifest rather than the full JSON blob.
- Full state is stored as checksummed pages; only missing/changed pages download.
- Ordinary saves send a revision-guarded JSON patch, not the complete snapshot.
- Very large patches use checksummed staged uploads and one atomic final commit.
- Operation IDs are acknowledged in the SAME transaction as the state update.
  A timed-out response can be retried without applying an edit twice.
- The original warehouse_state remains the authority. Updates from old clients
  also update the page cache, but older clients still generate heavy requests.
- Realtime uses small revision broadcasts; two-second polling remains fallback.
- Android background receiving also uses persistent page caches and small reads.
- Products, profiles, photos, reports, all history and original indices are kept.
  No archived data was trimmed to reduce the response size.
- V99 IndexedDB cache storage and safe legacy migration remain included.
